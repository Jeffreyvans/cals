# Deploying EduSphere on Render

This guide takes a fresh clone to a working production deployment on
[Render](https://render.com), with PostgreSQL, object storage and email. It
also covers the optional custom domain, password rotation, a go-live checklist
and the errors you are most likely to hit.

The repository ships two files that do the work:

* `build.sh` – installs dependencies, collects static files, runs migrations
  and creates the main platform administrator.
* `render.yaml` – a Render Blueprint describing the web service, the health
  check, the start command and every environment variable.

Nothing in either file contains a real secret. The administrator username,
email and password are read from the Render dashboard at deploy time.

---

## 1. What gets created

| Piece | Where it lives | Notes |
| --- | --- | --- |
| Web process | Render Python web service | `gunicorn config.wsgi:application` |
| Static files | Render disk, served by WhiteNoise | collected by `build.sh`, hashed and compressed |
| Database | External PostgreSQL (Render, Supabase, Neon, …) | `DATABASE_URL`; SQLite only for local development |
| Uploaded files | S3-compatible bucket (Supabase Storage, Cloudflare R2, Backblaze B2) | Render's free disk is ephemeral |
| Email | Resend HTTPS API (django-anymail) | console backend in local development |
| Health check | `GET /health/` | returns `200 {"status":"ok"}` when the database answers |
| Platform admin | `accounts.User` + `platform_admin.PlatformStaff` | created from environment variables |

`build.sh` runs on **every** deploy and is idempotent. It will not overwrite
the administrator password unless `PLATFORM_ADMIN_RESET_PASSWORD=true` is set
for that one deploy.

---

## 2. Before you start

You need:

1. A [Render account](https://dashboard.render.com/register).
2. This repository pushed to GitHub, GitLab or Bitbucket.
3. A PostgreSQL database. Render can create one, or you can use Supabase
   (recommended if you already use it). See section 5.
4. An S3-compatible bucket for uploads. See section 6.
5. A [Resend](https://resend.com) API key and a verified sending domain.
   Render's free plan blocks outbound SMTP, so email always goes over
   Resend's HTTPS API. See section 7.
6. A strong administrator password (**at least 10 characters**, not all
   digits, not a common password, not too similar to the username or email).

Keep the administrator password in a password manager. You will type it into
Render once; it is never stored in the repository.

---

## 3. Deploy with the Blueprint (click by click)

1. Sign in to <https://dashboard.render.com>.
2. Click **New +** in the top right, then **Blueprint**.
3. Connect your Git provider and pick the EduSphere repository.
4. Give the Blueprint a name (for example `edusphere`) and confirm the branch
   (usually `main`).
5. Render reads `render.yaml` and shows the `edusphere` web service.
6. Click **Apply** / **Create**.
7. Render asks for every variable marked `sync: false`. Fill in:
   * `PLATFORM_ADMIN_USERNAME` – the sign-in name, e.g. `platform-admin`.
   * `PLATFORM_ADMIN_EMAIL` – a mailbox you control.
   * `PLATFORM_ADMIN_PASSWORD` – the strong password from your manager.
   * `DATABASE_URL` – the PostgreSQL URL from section 5.
   * `RESEND_API_KEY`, `DEFAULT_FROM_EMAIL`, `SERVER_EMAIL`,
     `EMAIL_FROM_DOMAIN`, `SITE_URL` and `RESEND_WEBHOOK_SECRET` – from
     section 7.
   * `STORAGE_BACKEND` and the `AWS_*` keys – from section 6.
8. `SECRET_KEY` is generated by Render automatically. `DEBUG` is already
   `false`.
9. Click **Deploy**. The first build takes a few minutes.
10. Watch the **Logs** tab. A successful deploy ends with the gunicorn worker
    boot lines and no traceback.
11. Open the service URL (`https://<service-name>.onrender.com`). The sign-in
    page should load with HTTPS.
12. Sign in with the administrator username and password you entered. Because
    `PLATFORM_ADMIN_FORCE_CHANGE` defaults to `true`, you are sent straight to
    **Choose a new password**. Pick a new strong password that is **different
    from the environment one**. This clears the warning banner on the platform
    dashboard.

### Deploy without the Blueprint (manual service)

If you prefer not to use `render.yaml`:

1. **New + → Web Service**, connect the repository.
2. Runtime: **Python 3**.
3. Build command: `./build.sh`
4. Start command:
   `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --timeout 120`
5. Health check path: `/health/`
6. Add the environment variables from section 4. Set `PYTHON_VERSION` to
   `3.12.10`, `DEBUG` to `false`, and generate `SECRET_KEY`.
7. Deploy.

> **Executable bit:** Render runs `./build.sh`, so the file must be executable
> in git. This repository sets that bit. If you copy the file by hand, run
> `git add --chmod=+x build.sh` and commit before deploying.

## 4. Environment variables

The generic names are the ones Render and other hosts understand. The older
`EDUSPHERE_*` names still work as fallbacks, so an existing local `.env` keeps
working. A real environment variable always wins over `.env`.

### Core

| Variable | Required | Purpose |
| --- | --- | --- |
| `DEBUG` | Production: `false` | Turns on development behaviour. Render sets `false`; with no variables at all it defaults to `true` locally. |
| `SECRET_KEY` | Yes in production | Django signing key. Render generates it (`generateValue: true`). Never reuse a development key. |
| `ALLOWED_HOSTS` | Yes in production | Comma-separated hostnames, e.g. `edusphere.example.com`. `RENDER_EXTERNAL_HOSTNAME` is appended automatically. |
| `CSRF_TRUSTED_ORIGINS` | For a custom domain | Comma-separated full origins, e.g. `https://edusphere.example.com`. `https://<RENDER_EXTERNAL_HOSTNAME>` is appended automatically. |
| `RENDER_EXTERNAL_HOSTNAME` | Automatic | Set by Render. Used to add the host and CSRF origin automatically. |
| `SECURE_SSL_REDIRECT` | No (default `true`) | Redirects HTTP to HTTPS when `DEBUG=false`. |
| `SECURE_HSTS_SECONDS` | No (default `31536000`) | HSTS lifetime when `DEBUG=false`. |
| `PYTHON_VERSION` | Yes on Render | Pinned to `3.12.10` in `render.yaml`. |
| `PYTHONUNBUFFERED` | Recommended | `1` so build and runtime logs appear immediately. |

### Database

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | Yes in production | Full PostgreSQL URL. Without it the app uses local SQLite. |
| `DB_SSL_MODE` | Recommended | `require` for hosted PostgreSQL. Defaults to `require` when `DEBUG=false`. |
| `EDUSPHERE_DB_PATH` | Local only | SQLite file path when `DATABASE_URL` is empty. |

### Main platform administrator

| Variable | Required | Purpose |
| --- | --- | --- |
| `PLATFORM_ADMIN_USERNAME` | Yes | Sign-in name for the main platform administrator. |
| `PLATFORM_ADMIN_EMAIL` | Yes | Email address for the account. Verified automatically. |
| `PLATFORM_ADMIN_PASSWORD` | Yes | Initial password. Validated against Django's validators; stored hashed only; never printed. |
| `PLATFORM_ADMIN_RESET_PASSWORD` | No (default `false`) | Set to `true` for **one** deploy to replace the existing password. Set it back to `false` afterwards. |
| `PLATFORM_ADMIN_FORCE_CHANGE` | No (default `true`) | Forces a new password at first sign-in and keeps the dashboard warning until the password is changed. |

The account is created with `is_platform_admin`, `is_staff`, `is_superuser`
and `is_active` all true, role `admin`, no institution, a verified email and a
`PlatformStaff` row with the `main_admin` role. Running the command twice
changes nothing; it never creates a duplicate.

### Static and uploaded files

| Variable | Required | Purpose |
| --- | --- | --- |
| `STORAGE_BACKEND` | Production: yes | `local`, `s3`, `r2`, `b2` or `supabase`. Anything other than `local` switches uploads to the S3 API. |
| `AWS_ACCESS_KEY_ID` | With S3 storage | Access key for the bucket. |
| `AWS_SECRET_ACCESS_KEY` | With S3 storage | Secret key for the bucket. |
| `AWS_STORAGE_BUCKET_NAME` | With S3 storage | Bucket name. |
| `AWS_S3_ENDPOINT_URL` | For R2/B2/Supabase | S3 endpoint, e.g. `https://<project>.supabase.co/storage/v1/s3`. |
| `AWS_S3_REGION_NAME` | With S3 storage | `auto` for R2; the bucket region for B2/Supabase. |
| `AWS_S3_CUSTOM_DOMAIN` | Optional | Public CDN domain for files. |
| `AWS_LOCATION` | Optional | Key prefix inside the bucket, e.g. `edusphere`. |
| `EDUSPHERE_MEDIA_PATH` | Local only | Folder for uploads when storage is `local`. |

### Email

| Variable | Required | Purpose |
| --- | --- | --- |
| `RESEND_API_KEY` | Yes in production | API key from <https://resend.com/api-keys>. With no key the console backend is used. |
| `DEFAULT_FROM_EMAIL` | Yes | The From address on every message. Must be on the verified domain. |
| `SERVER_EMAIL` | Recommended | Address for platform/system mail. Defaults to `DEFAULT_FROM_EMAIL`. |
| `EMAIL_FROM_DOMAIN` | Recommended | The verified sending domain, used to build the default From address. |
| `SITE_URL` | Yes | Public base URL (https) used for links in email, e.g. `https://app.onrender.com`. |
| `RESEND_WEBHOOK_SECRET` | Optional | `whsec_…` secret that verifies the Resend delivery webhook. |
| `EMAIL_TIMEOUT` | No | Seconds before the provider gives up. Default `10`. |
| `EMAIL_ASYNC` | No | `true` only when a Celery worker is running. Default `false` (send inline). |
| `EMAIL_MAX_RETRIES`, `EMAIL_RETRY_BACKOFF_SECONDS` | No | Delivery retries. Defaults `5` and `60`. |
| `EMAIL_VERIFY_LIMIT`, `EMAIL_RESET_LIMIT`, `EMAIL_IP_LIMIT` | No | Per-address and per-IP limits. Defaults `5`, `5`, `20`. |
| `EMAIL_BULK_LIMIT`, `EMAIL_RATE_WINDOW_SECONDS` | No | Per-institution bulk cap and window. Defaults `500`, `3600`. |
| `RESEND_API_URL` | No | Base URL used by django-anymail. Defaults to `https://api.resend.com/`. |

There are deliberately no `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USE_TLS` or
`EMAIL_USE_SSL` settings: nothing in the app can open an SMTP connection.

### School identity

| Variable | Purpose |
| --- | --- |
| `EDUSPHERE_INSTITUTION_NAME` | Default institution name used on a fresh install. |
| `EDUSPHERE_CURRENCY` | Default currency symbol. |
| `EDUSPHERE_TIME_ZONE` | Default time zone (default `Africa/Harare`). |

### Optional integrations

| Variable | Purpose |
| --- | --- |
| `PAYNOW_INTEGRATION_ID`, `PAYNOW_INTEGRATION_KEY` | Paynow Zimbabwe credentials. |
| `PAYNOW_MODE` | `test` or `live`. |
| `PAYNOW_RETURN_URL`, `PAYNOW_RESULT_URL` | Callback URLs. |
| `EDUSPHERE_FISCALISATION_ENABLED` | Turn fiscalisation on/off. |
| `EDUSPHERE_FISCALISATION_GATEWAY` | `mock` or the live gateway. |
| `EDUSPHERE_ZIMRA_FDMS_URL`, `EDUSPHERE_ZIMRA_DEVICE_ID`, `EDUSPHERE_ZIMRA_DEVICE_SERIAL`, `EDUSPHERE_ZIMRA_API_KEY` | ZIMRA FDMS details. |
| `EDUSPHERE_FINANCE_BACKUP_KEY` | Fernet key for encrypted finance backups. Generate with `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. |

`.env.example` lists the same variables with obvious placeholders for local
use.

## 5. Connect PostgreSQL

### Option A – Render PostgreSQL

1. In Render: **New + → PostgreSQL**.
2. Choose a name, region and plan.
3. After it is ready, open the database and copy the **Internal Database URL**
   (same region, recommended) or the **External Database URL**.
4. Paste it into the web service's `DATABASE_URL` and redeploy.

### Option B – Supabase (session pooler, recommended)

1. Create a project at <https://supabase.com>.
2. Open **Project Settings → Database**.
3. Find **Connection string → Session pooler** (not the transaction pooler)
   and copy the URI. It looks like:

   ```text
   postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres
   ```

4. URL-encode special characters in the password (`@` → `%40`, `#` → `%23`,
   and so on).
5. Set `DATABASE_URL` to that value and `DB_SSL_MODE=require`.
6. Redeploy. `build.sh` runs `migrate` before the web process starts, so the
   schema is created automatically.

> Use the **session pooler** (port `5432`) for a long-lived Django process.
> The transaction pooler (port `6543`) is intended for short-lived serverless
> functions and can break session-level features.
>
> If your network requires IPv4, use the session pooler host; Supabase's direct
> database host may be IPv6-only.

### Option C – Neon or another provider

Create a database, copy its pooled PostgreSQL URL into `DATABASE_URL`, set
`DB_SSL_MODE=require`, and redeploy.

`build.sh` always runs `python manage.py migrate --noinput` before starting
the web process, so no manual migration step is needed.

## 6. Object storage for uploads (Supabase Storage, R2, B2)

Render's free filesystem is **ephemeral**: files uploaded through the app
disappear on the next deploy or restart. Production must use an S3-compatible
bucket. Static files are handled separately by WhiteNoise and do not need a
bucket.

### Supabase Storage

1. In Supabase, open **Storage** and create a private bucket, e.g.
   `edusphere-media`.
2. Open **Project Settings → Storage → S3 connection** and copy the endpoint,
   region and access keys. The endpoint is usually
   `https://<project-ref>.supabase.co/storage/v1/s3`.
3. Set:

   ```text
   STORAGE_BACKEND=supabase
   AWS_ACCESS_KEY_ID=<access key id>
   AWS_SECRET_ACCESS_KEY=<secret access key>
   AWS_STORAGE_BUCKET_NAME=edusphere-media
   AWS_S3_ENDPOINT_URL=https://<project-ref>.supabase.co/storage/v1/s3
   AWS_S3_REGION_NAME=<region from the S3 connection panel>
   AWS_LOCATION=edusphere
   ```

### Cloudflare R2

1. Create an R2 bucket and an API token with object read/write permission.
2. Copy the S3 endpoint (`https://<account-id>.r2.cloudflarestorage.com`).
3. Set `STORAGE_BACKEND=r2`, the endpoint, `AWS_S3_REGION_NAME=auto`, the
   bucket name and the token's access key/secret.

### Backblaze B2

1. Create a bucket and an application key.
2. Use the S3 endpoint shown for the bucket
   (`https://s3.<region>.backblazeb2.com`).
3. Set `STORAGE_BACKEND=b2`, the endpoint, the region, the bucket name and the
   key ID/application key.

Files are stored privately and served through short-lived signed URLs
(`AWS_QUERYSTRING_AUTH=True`), so a private bucket is the safe default.

## 7. Email

EduSphere sends every email through [Resend](https://resend.com)'s HTTPS API
using `django-anymail`. This works on Render's free plan, which blocks
outbound SMTP on ports 25, 465 and 587. There is no SMTP fallback.

### Setup

1. Create an account at <https://resend.com> and an API key at
   <https://resend.com/api-keys>.
2. Add and verify your sending domain under **Domains** (add the DNS records
   Resend shows). A `no-reply@yourdomain.com` sender only works once the
   domain shows **Verified**.
3. Set these Render environment variables:
   * `RESEND_API_KEY` – the API key.
   * `EMAIL_FROM_DOMAIN` – your verified domain, e.g. `yourdomain.com`.
   * `DEFAULT_FROM_EMAIL` – e.g. `EduSphere <no-reply@yourdomain.com>`.
   * `SERVER_EMAIL` – usually the same address.
   * `SITE_URL` – `https://<service-name>.onrender.com` (or your custom
     domain). Links in email are built from this, so background jobs send
     working links.
4. Redeploy. Then send yourself a test message:

   ```bash
   python manage.py check_email --to you@example.com
   ```

   It prints the provider status, message id and a sanitized response. The API
   key is never printed.
5. Optional but recommended: add the delivery webhook. In Resend open
   **Webhooks → Add endpoint**, use
   `https://<your-domain>/webhooks/resend/`, select the `email.delivered`,
   `email.bounced` and `email.complained` events, and copy the signing secret
   into `RESEND_WEBHOOK_SECRET`. Bounces and complaints then appear on the
   platform **Email health** page, and hard-bounced or complaining addresses
   are suppressed automatically.

In local development (no `RESEND_API_KEY`) the console backend prints messages
to the terminal, so no email account is needed.

## 8. Add a custom domain

1. In Render, open the web service → **Settings → Custom Domains**.
2. Click **Add Custom Domain** and enter `edusphere.example.com`.
3. Render shows the DNS record to create. At your DNS provider add either:
   * a `CNAME` from `edusphere` to the Render hostname, or
   * the `ALIAS`/`ANAME` record Render recommends for an apex domain.
4. Wait for Render to show **Certificate issued** (usually a few minutes).
5. Add the domain to the service environment:

   ```text
   ALLOWED_HOSTS=edusphere.example.com
   CSRF_TRUSTED_ORIGINS=https://edusphere.example.com
   ```

6. Redeploy. The host and CSRF origin may also inherit
   `RENDER_EXTERNAL_HOSTNAME`, but list the custom domain explicitly.
7. Sign in through the custom domain and check that static files and uploads
   still load.

HTTPS, secure cookies, the proxy header, SSL redirect and HSTS are enabled
automatically whenever `DEBUG=false`.

## 9. First sign-in and password rotation

### First sign-in

1. Open the service URL.
2. Sign in with `PLATFORM_ADMIN_USERNAME` and `PLATFORM_ADMIN_PASSWORD`.
3. You are redirected to **Choose a new password**.
4. Choose a new strong password that is different from the environment one.
5. You land on the platform dashboard. The environment-password warning is
   gone once the new password is saved.

### Rotate the password later

**Preferred – from the app:**

1. Sign in as the platform administrator.
2. Open **Two-factor and password → Change the password**.
3. Enter the current password and a new strong password.
4. In Render, open **Environment** and replace `PLATFORM_ADMIN_PASSWORD` with
   a new random value (it will **not** be applied while
   `PLATFORM_ADMIN_RESET_PASSWORD=false`). This removes the old secret from
   the dashboard.
5. Redeploy. The account keeps the password you chose in step 3.

**Recovery – if you are locked out:**

1. In Render, set `PLATFORM_ADMIN_PASSWORD` to a new strong password and set
   `PLATFORM_ADMIN_RESET_PASSWORD=true`.
2. Deploy once.
3. Sign in with the new password. The first-login flow asks you to choose
   another password.
4. Set `PLATFORM_ADMIN_RESET_PASSWORD=false` and replace
   `PLATFORM_ADMIN_PASSWORD` with a new unused value.
5. Redeploy.

The password is only ever transmitted to Django's `set_password`, which stores
a hash. It is never printed in build logs, application logs or command output.

## 10. Go-live checklist

- [ ] `DEBUG=false` in Render.
- [ ] `SECRET_KEY` generated by Render (not a development key).
- [ ] `ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS` include every real domain.
- [ ] `DATABASE_URL` points at PostgreSQL and `DB_SSL_MODE=require`.
- [ ] A deploy has run `migrate` successfully (check the build logs).
- [ ] `GET https://<domain>/health/` returns `200` with
      `{"status":"ok","database":"ok"}`.
- [ ] The platform administrator can sign in and has changed the initial
      password.
- [ ] The dashboard warning about the environment password is gone.
- [ ] Uploads are configured (`STORAGE_BACKEND` not `local`) and a test upload
      survives a redeploy.
- [ ] Email sends successfully (invite a test user or reset a password).
- [ ] Static files load over HTTPS (no unstyled pages, no 404s in the
      browser console).
- [ ] Two-factor authentication is enabled for the platform administrator.
- [ ] The custom domain shows a valid certificate and redirects HTTP to HTTPS.
- [ ] A database backup/retention policy exists (Render/Supabase dashboard).
- [ ] `PLATFORM_ADMIN_RESET_PASSWORD` is `false`.
- [ ] Optional integrations (Paynow, ZIMRA, finance backup key) are configured
      or deliberately left off.

## 11. Troubleshooting

### The build fails with `./build.sh: Permission denied`

The executable bit is missing in git. Locally run:

```bash
git add --chmod=+x build.sh
git commit -m "Make build.sh executable"
git push
```

Then redeploy.

### `ImproperlyConfigured: SECRET_KEY must be set when DEBUG is off`

Add `SECRET_KEY` to the service environment (or redeploy the Blueprint so
Render generates it).

### `ImproperlyConfigured: ALLOWED_HOSTS must list your domain(s)`

Set `ALLOWED_HOSTS`, or make sure Render's `RENDER_EXTERNAL_HOSTNAME` is
present. A custom domain must be added explicitly.

### `DisallowedHost` or `400 Bad Request` after adding a domain

Add the domain to `ALLOWED_HOSTS` and redeploy.

### `CSRF verification failed` when submitting a form

Add the exact origin (including `https://`) to `CSRF_TRUSTED_ORIGINS`, then
redeploy. Do not include a trailing slash.

### `relation "..." does not exist`

Migrations did not run. Check that `build.sh` is the build command and that
the `migrate` step is in the build logs. If you changed the database URL,
redeploy so migrations run against the new database.

### Database connection refused, timed out, or `SSL required`

* Confirm `DATABASE_URL` is the **session pooler** URL for Supabase.
* Set `DB_SSL_MODE=require`.
* URL-encode special characters in the password.
* If the host is IPv6-only, use the session pooler host.

### `502 Bad Gateway` or the service keeps restarting

* Open the logs and look for a traceback above the gunicorn lines.
* Check `SECRET_KEY`, `ALLOWED_HOSTS` and `DATABASE_URL`.
* On the free plan the service sleeps after inactivity; the first request can
  take a while to wake it.
* If a request takes longer than 120 seconds, raise the gunicorn `--timeout`
  in the start command (the Blueprint uses `120`).

### The platform administrator was not created

1. Confirm all three of `PLATFORM_ADMIN_USERNAME`, `PLATFORM_ADMIN_EMAIL` and
   `PLATFORM_ADMIN_PASSWORD` are set on the **web service** (not only in a
   local `.env`).
2. Search the build logs for `Platform administrator was not created`. The
   message names the missing variable or the validation rule.
3. Passwords must be at least 10 characters, not all digits, not a common
   password, and not too similar to the username or email.
4. If the account exists and you want to replace the password, set
   `PLATFORM_ADMIN_RESET_PASSWORD=true` for one deploy.
5. Run the command manually from a Render shell:

   ```bash
   python manage.py ensure_platform_admin
   ```

### Sign-in works but every page redirects to “Choose a new password”

That is `PLATFORM_ADMIN_FORCE_CHANGE=true` (the default) while the account
still has a temporary password. Complete the password change.

### The platform dashboard keeps warning about the environment password

The account still has `password_set_from_env=true`. Change the password from
**Two-factor and password → Change the password**; the flag clears when you
save a new password.

### Uploaded files disappear after a deploy

Render's filesystem is ephemeral. Configure S3-compatible storage (section 6)
and set `STORAGE_BACKEND` to `s3`, `r2`, `b2` or `supabase`.

### Static files are missing or pages are unstyled

* Confirm the build logs contain `static files copied` and
  `post-processed`.
* Confirm `WhiteNoiseMiddleware` is present (it is, in `config/settings.py`).
* Run `python manage.py collectstatic --noinput` locally to reproduce a
  missing-asset error before deploying.
* Do not point `STATIC_ROOT` at a folder that is deleted by the build.

### `collectstatic` reports a missing manifest entry

A template or stylesheet references a file that is not in `static/`. Add the
file, run `collectstatic` again, and redeploy. The manifest storage fails the
build rather than silently serving a 404.

### `python: command not found` in the build

The Blueprint pins `PYTHON_VERSION=3.12.10`. If you built the service
manually, add that variable and redeploy.

### Email is not arriving

* Run `python manage.py check_email --to you@example.com` on the deployed
  service (Render shell) and read the printed provider response.
* Open **Platform → Email health** to see the last 50 messages, failures and
  bounce/complaint counts, and to resend a failed message.
* The most common cause is an unverified sending domain: `DEFAULT_FROM_EMAIL`
  must use the domain you verified in Resend.
* Check that `SITE_URL` is set. Links are built from it, never from the
  request host, so a missing value produces wrong links in background mail.
* If `RESEND_WEBHOOK_SECRET` is set but the endpoint returns `400`, the secret
  does not match the one in Resend. Remove it to disable the webhook until the
  secret is corrected.
* A failed send never crashes the page: the user sees
  "We could not send the email. Try again in a few minutes" and the attempt is
  retried with backoff up to five times.

### Local development stopped working

With no environment variables the app still runs on SQLite with `DEBUG=true`
and the console email backend:

```bash
python -m venv venv
# Windows: venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed
python manage.py runserver
```

Copy `.env.example` to `.env` only when you need to override something.

## 12. Useful commands

```bash
# Run the full test suite
pytest

# Lint
python -m ruff check .

# Check for missing migrations
python manage.py makemigrations --check --dry-run

# Production configuration check (PowerShell example)
$env:DEBUG="false"
$env:SECRET_KEY="<long random string>"
$env:ALLOWED_HOSTS="edusphere.example.com"
$env:CSRF_TRUSTED_ORIGINS="https://edusphere.example.com"
python manage.py check --deploy

# Provision or repair the administrator by hand
python manage.py ensure_platform_admin

# Force a password replacement for this run
PLATFORM_ADMIN_RESET_PASSWORD=true python manage.py ensure_platform_admin
```

The `create_platform_admin` command still exists for adding additional
platform staff with a specific platform role.
